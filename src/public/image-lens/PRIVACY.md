# Privacy Policy

千寻助手的图片反推功能整合自 ImageLens，支持 BOFT.AI OAuth 登录或自备 API Key。LIBERSEEK 不运营中转图片和密钥的服务器。

## 本地保存的数据

插件会使用 `chrome.storage.local` 在当前浏览器本地保存以下配置：

- 用户填写的 API Key，或 BOFT.AI OAuth 签发的当前扩展 AUTO Key
- BOFT.AI 账号邮箱、标识和 OAuth 客户端注册信息
- 用户选择的服务商
- 用户填写的模型名称
- 用户填写的 Base URL
- 是否开启自动识别
- 是否开启中文提示词识别
- 是否开启生图功能
- 默认生图比例和出图张数

这些配置不会写入代码仓库，也不会发送给项目作者。

## 发送到外部 API 的数据

当用户主动点击网页图片上的识别按钮时，插件会优先直接读取该图片，并将图片数据和图片 alt 文本发送到用户当前配置的识图服务商，用于生成提示词。较大的图片会先在本地缩小到长边 1600 像素以内再发送。页面地址只用于读取图片时作为来源信息，不会发送给识图服务商。

如果目标网站限制了图片直接读取，插件会在本地对当前可见标签页进行一次截图，并仅裁剪出用户刚刚点击的图片区域；发送到外部 API 的是裁剪后的图片片段，不是整页截图。

当用户通过右键菜单分析 canvas 或视频画面，或主动使用「框选区域分析」（右键菜单、工具栏图标或快捷键）拖动框选页面区域时，插件同样会在本地对当前可见标签页截图，并仅裁剪出该元素或用户框选的区域，再发送给用户当前配置的识图服务商。

当用户主动点击「立刻生图」时，插件会将当前提示词、生图比例和出图张数发送到用户当前配置的生图服务商，用于生成图片。

这些外部 API 可以是 BOFT.AI、Google Gemini，也可以是用户自行配置的 OpenAI-compatible 服务或 Base URL。用户填写的 API Key 只会在用户主动读取模型、识别或生图时，用于向当前选择的服务商发起请求，不会发送给项目作者。

外部 API 对这些数据的处理方式，受对应服务商自己的服务条款和隐私政策约束。

## 不收集的数据

项目作者不会收集、存储或分析以下数据：

- 用户的 API Key
- 用户浏览的网页内容
- 用户识别的图片内容
- 用户生成或编辑的提示词
- 用户生成的图片结果

## 权限说明

- `storage`：用于在本地保存插件配置。
- `contextMenus`：用于在右键菜单中加入「分析这里的图片」和「框选区域分析」两个入口，只在用户点击菜单项时触发识别或框选。
- `<all_urls>`：用于在网页图片上注入识别按钮，在用户主动点击后读取对应图片，并在个别网站限制直接读取图片时，本地裁剪当前可见图片区域用于识别。
- `https://generativelanguage.googleapis.com/*`：用于将用户主动触发的 Gemini 请求发送到 Gemini API。OpenAI-compatible 请求会发送到用户自己配置的 Base URL。

插件只会在用户主动登录、读取模型、识别或生图时调用对应外部 API。

## BOFT.AI OAuth

使用 `identity` 权限打开 `https://supply.boft.ai` 授权页，通过 PKCE S256 和 state 校验取得临时 token，验证账号并签发当前扩展 OAuth 客户端绑定的 AUTO Key。临时 token 在签发后撤销，不持久保存。AUTO Key 留在插件后台，识图与生图共用，不返回网页脚本。

模型与图片请求发送至 `https://api-direct.boft.ai`。断开连接只删除本机 OAuth 凭据，手动密钥独立保留；服务端密钥需在 BOFT.AI 管理中撤销。丢失本地密钥后重新授权，可能替换当前客户端绑定的旧密钥。模型调用可能产生账户费用。
