# B站社媒数据采集

B站与抖音、小红书共用千寻助手的任务弹窗、进度面板、停止/重试和 Excel 导出流程，无需单独配置模型 API。

## 使用方式

1. 重新加载 `output/chrome-mv3` 扩展，并刷新B站页面；建议先在B站登录。
2. 打开插件，在B站主页、视频页或UP主空间中选择采集任务。其他网页的「社媒数据」列表也有哔哩哔哩入口。
3. 填写完整链接、采集数量和请求间隔，点击「开始」。默认间隔为1秒；出现平台限制时请在网页完成验证，并在稍后增加间隔重试。
4. 处理完成后点击「导出数据」保存 `.xlsx`。任务失败或中止时也可以导出已获取的数据，或点击「重试」。

视频信息区和UP主空间头部沿用单个千寻图标菜单，视频播放区域不新增悬浮快捷入口。

## 四类任务

| 任务 | 输入 | 导出内容 |
| --- | --- | --- |
| UP主信息 | `https://space.bilibili.com/2`（支持空间子页） | UID、昵称、简介、粉丝、关注、获赞、投稿数、等级、认证及头像 |
| 指定视频 | `https://www.bilibili.com/video/BV1xx411c7mD` 或 `/video/av2`，也支持 `https://b23.tv/…` 短链接 | BV/AV号、链接、标题、简介、分区、UP主、播放、弹幕、点赞、投币、收藏、分享、评论数、发布时间、时长及封面 |
| UP主投稿 | UP主空间链接和每位UP主的数量 | 按最新投稿分页，逐条获取视频详情；导出字段同上 |
| 视频评论 | 视频链接和每条视频的数量 | 评论ID、正文、作者、时间、点赞、回复数、IP属地（如平台返回）、根/父评论ID及评论图片链接 |

评论任务可选择包含楼中楼。一级评论和楼中楼合计计入数量限制，去重后截断；评论ID优先保留平台返回的字符串，避免大整数精度丢失。视频/UP主数量上限为10000（逐条链接任务除外）；平台不返回或不可访问的数据不会被补造。

## 视频和图片下载

- 视频信息区菜单支持「下载当前分P视频」「下载全部分P视频」；视频及UP主投稿任务完成后，可在「下载素材」中批量下载全部分P的MP4。也可下载封面、UP主头像和评论图片。
- 使用B站HTML5播放接口请求音画合一MP4，申请最高720P；平台可能返回较低清晰度，文件名标明实际清晰度、BV号和P序号。多段MP4分别保存，不做拼接。
- 每条视频在加入下载队列前解析临时地址，通过Chrome原生下载保存，避免将完整视频载入插件内存。视频文件保存在下载目录的 `B站/` 下。
- 若平台只提供DASH音视频分离流，或仅返回试看内容，会明确提示。此版本不内置FFmpeg合并，也不提升账号已有访问权限。
- 弹幕字段是数量，本版不采集弹幕正文。

## 下载方案参考

接口及格式处理参考 [yt-dlp Bilibili extractor](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py) 和 [yutto UGC播放接口](https://github.com/yutto-dev/yutto/blob/main/src/yutto/api/ugc_video.py) 中的 `cid`、`playurl`与 `durl` 的格式处理方式；本扩展按现有任务和Chrome下载架构实现，没有嵌入这两个桌面下载器。

## 验证范围

- `pnpm compile`、`pnpm build`。
- `pnpm exec node --test tests/bilibili.test.mjs`：链接验证、WBI参数与签名刷新、平台错误、数据字段、投稿/评论分页去重、数量限制、取消、部分导出、分P/实际清晰度、MP4选择及试看/DASH拒绝。
- Chromium 加载构建后的真实扩展，使用受控B站页面及接口数据验证四类任务，并检查生成的 Excel 内容，以及当前/全部分P、批量MP4下载；此验证不代表真实登录会话下的采集成功。
- 真实浏览器匿名检查已取得公开视频与UP主资料，并由播放接口取得音画合一720P MP4地址，Chrome原生下载已收到约1 MB真实视频数据后主动取消；投稿/评论检查受到平台 HTTP 412 限制。完整在线分页仍需在有权访问的B站登录会话中验证。
